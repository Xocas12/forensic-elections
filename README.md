# forensic-elections

Statistical forensics of strategically reported data — the **elections** calibration project.
One of two project repositories that share the
[`forensics-core`](packages/forensics_core/) method library (a git submodule); the other is
`forensic-economy` (`aaer`, `china`, `gosplan`).

## Result

Two of the three validation anchors are reproduced on 192,924 precinct protocols from the
2011 State Duma and 2018 presidential elections. Full report, with the controls and the
caveats: **[RESULTS.md](RESULTS.md)**.

**Anchor 1 — excess mass at integer percentages** (Kobak, Shpilkin and Pshenichnikov 2016).
Against a per-station binomial null, with the paper's exclusion of stations over 99% turnout
or winner's share, reported percentages land on whole numbers more often than the arithmetic of
that station's size allows. Beside each excess, the bias the same procedure shows on honest data
simulated at the observed shares:

| election | quantity | excess stations | honest-data bias | z |
|---|---|---:|---:|---:|
| 2011 Duma | turnout | +408 | -18 ± 27 | 4.58 |
| 2011 Duma | winner's share | +763 | +2 ± 27 | 9.18 |
| 2018 presidential | turnout | +1,203 | -65 ± 20 | 13.12 |
| 2018 presidential | winner's share | +840 | -42 ± 18 | 9.01 |

The finding survives the control that matters. Small stations hit whole percentages honestly,
so an arithmetic artefact would be largest among them and vanish among large ones. It runs the
other way: flat below 250 registered voters and rising with station size, strongest at 1,000
to 5,000. Tatarstan, Dagestan and Bashkortostan are in the top ten regions by excess per
station in both elections, with z between 4.9 and 11.7; whether that matches the paper's own
regional list is not yet checked.

**Anchor 3 — a second turnout mode** (Klimek et al. 2012). Silverman's critical-bandwidth test
rejects unimodality in both elections at the bootstrap floor (p = 0.001). The second mode sits
within two points of complete turnout, and the winner's share there is far above the share at
the principal mode.

**Anchor 2 — the comet tail — was not run.** Its estimator has not been read from a primary
source, so it still raises `NotImplementedError` with that reason in the message. Writing a
plausible-looking tail estimator from memory would produce a number with nothing to check it
against, which is the failure this project is built to avoid.

**What is not claimed.** These are distributional anomalies against a stated null, not proof
about any polling station. The Poland and Spain false-positive controls are still outstanding.
Anchor 3 does not separate falsification from genuine urban/rural heterogeneity, and does not
claim to. [RESULTS.md](RESULTS.md) says all of this at greater length.

## The programme

Three of four projects have ground truth; one does not. Methods are developed and scored
where truth is knowable, then carried to the Soviet case where it is not.

| Project | Repository | Labels | Role |
|---|---|---|---|
| `elections` | **this repo** | Strong (published signatures, replicable prior findings) | Calibrate digit and bunching methods |
| `aaer` | forensic-economy | Strong (SEC enforcement actions as positives) | Calibrate supervised / PU learning, benchmark against published AUC |
| `china` | forensic-economy | Partial (self-admitted falsification, a statistical-reform discontinuity) | Calibrate cross-source reconciliation against physical proxies |
| `gosplan` | forensic-economy | Almost none (one anchor event) | **The target.** Methods validated above are transferred here |

**Unifying hypothesis.** Distortion concentrates at discontinuities in the incentive
function. Here the notch is the round-number vote share and turnout figure; the shared
library makes "find the notch, estimate excess mass around it" a first-class operation.

This repository is the calibration step: it is where the methods are shown to recover a known
answer before they are pointed at a case where the answer is unknown.

## This project

**Question.** Reproduce known falsification signatures in Russian federal elections (2011
State Duma, 2018 presidential) at precinct level, and quantify how much detection power comes
from each family of method. See [projects/elections/README.md](projects/elections/README.md)
for data status and current state, and
[projects/elections/docs/](projects/elections/docs/) for the research question, data
dictionary, validation anchors and known traps.

## How to run

Requirements: [`uv`](https://docs.astral.sh/uv/), GNU make, git. Python 3.12 is pinned.

```sh
git clone --recurse-submodules <this repo>     # or: make submodule after a plain clone
make setup          # submodule init + uv sync --all-packages + pre-commit hooks
make test
make lint

# Put a real name and email in config/forensics.toml ([http].contact) first — every
# network script refuses to run while the placeholder is in place.
make data                                                   # fetch the precinct tables
uv run python -m elections.clean --data-dir projects/elections/data
uv run python scripts/run_analysis.py                       # writes RESULTS.md
```

`make data` is idempotent: every successful fetch is checksummed and recorded in
`data/SOURCES.yaml`, every attempt is appended to `data/fetch_log.jsonl`, and a source is
never fetched twice unless forced. The analysis is seeded, so a re-run reproduces the tables
in `RESULTS.md` exactly.

## Rules the code enforces

1. No invented URLs: sources are verified by an actual fetch (HTTP status, bytes, SHA-256,
   timestamp) or recorded as `unverified` / `blocked` with a reason.
2. Every fetch attempt is logged.
3. No synthetic data under `data/`; fixtures live in `tests/fixtures/` with a `synthetic_` prefix.
4. Fail loudly and continue.
5. Raw data never enters git (`.gitignore` plus a pre-commit hook).
6. Access policies are respected: contact header, per-host rate limits, aggressive caching.
7. "Not found" and "not free" are different statuses.

Rule 1 earned its keep on the first real load. The column map had been written against a
source note that gave the 2011 party columns by their ballot abbreviations; the actual file
spells two of them out in full, and the header check refused to load it rather than
mis-aligning the columns silently. See the note on `RU_PARTIES` in
[`clean/schema.py`](projects/elections/src/elections/clean/schema.py).

## Status

914 tests pass. The acquisition pipeline, the cleaning layer and anchors 1 and 3 are
implemented and have been run end to end on the real precinct tables; the findings are in
[RESULTS.md](RESULTS.md). Anchor 2 is blocked on a primary source and says so in code. See
[DATA_STATUS.md](DATA_STATUS.md) for the source registry.
